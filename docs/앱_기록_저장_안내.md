# 앱에서 기록 저장하기 — 하영님용 안내

경험(`experience`)과 회차 기록(`experience_log`)은 **앱이 Supabase에 직접** 읽고 씁니다. 서버를 거치지 않습니다.
칸 목록 전체는 [API 명세](API_명세서.md) 1.1·1.2, DB 규칙 원본은 `db/000_soyun_record.sql`에 있습니다.

## 접속

- Supabase 초대를 수락하고 프로젝트 맨 위 **Connect** 버튼에서 `Project URL`과 **Publishable key**를 가져옵니다
- 앱에는 Publishable key만 넣습니다. **Secret key는 앱에 절대 넣지 않습니다**
- 테이블 모양을 TypeScript 타입으로 뽑기: `npx supabase gen types typescript --project-id <프로젝트 id> > types/supabase.ts`
  (프로젝트 id는 Project URL의 `https://<여기>.supabase.co` 부분)

## 경험 저장 (4단계까지 채운 뒤 한 번)

```js
const { data, error } = await supabase.from('experience').insert({
  status: 'done',                       // 'in_progress' | 'done'
  activity_name: '2026 과준위',          // 2~40자
  official_activity_id: null,           // 공식 활동을 골랐으면 그 id
  genre: '행사 운영',                    // 분야 9개 중 1 (아래 목록 글자 그대로)
  type: '학생회·행사',                   // 유형 7개 중 1, 안 골랐으면 null
  role: '총괄',                          // 2~20자
  period_start: '2026-03',              // "YYYY-MM"
  period_end: '2026-06',                // 진행 중이면 null. 시작보다 앞이면 안 됨
  place: null,                          // 30자
  did_chips: ['행사 기획'],               // 1~3개 (필수)
  did_notes: { '행사 기획': '부스 배치를 바꿨다' },   // { 칩: 보강글 } 보강글 80자
}).select().single()
```

- **`user_id`는 보내지 않습니다.** DB가 로그인한 사람으로 채웁니다
- 5~7단계 칸: `conditions`(`{ scale: [...], method: [...], my_role: [...], autonomy: [...] }`), `situation_chips`(최대 2), `situation_notes`(`{ 칩: 글 }` 80자), `emotion_chips`(최대 2), `one_liner`(100자)
- 그 밖에 앱이 쓸 수 있는 칸: `custom_chips`, `ai_tags`, `photos`, `pinned`
- **앱이 못 쓰는 칸**: `visibility`, `accept_questions`, `accept_coffeechat`, `published_snapshot`, `masked`, `published_at`, `embedding`. 보내면 권한 에러가 납니다. 공개 관련은 서버 API(`/publish/*`)로 합니다

### 분야·유형 목록 — 글자 그대로

가운뎃점은 `·`, `행사 운영`은 띄어쓰기를 포함합니다. 목록에 없는 글자는 DB가 거부합니다.

- 분야(`genre`, 필수): `행사 운영` `개발·IT` `디자인·콘텐츠` `음악·공연` `연구·실험` `교육·멘토링` `경영·마케팅` `서비스·응대` `기타`
- 유형(`type`, 선택): `동아리·학회` `팀플·공모전` `대외활동` `학생회·행사` `아르바이트` `봉사·멘토링` `수업·캡스톤`

## 저장 후 수정 — 버전 확인

```js
const { data, error } = await supabase.from('experience')
  .update({ one_liner: '고친 한 줄' })
  .eq('id', id)
  .eq('updated_at', lastSeen)   // 마지막으로 받은 updated_at
  .select('updated_at')
if (!error && data.length === 0) {
  // VERSION_CONFLICT: 다른 곳에서 먼저 고침 → 최신 내용을 다시 불러와서 보여주기
}
lastSeen = data[0].updated_at   // 다음 수정에 씀
```

- **`updated_at`은 받은 글자 그대로** 넘깁니다. `new Date()`로 바꾸면 밀리초 아래 자리가 잘려서 항상 충돌로 나옵니다
- `.select()`를 붙여야 몇 행이 바뀌었는지 알 수 있습니다

## 보관소 목록 (최신순, cursor)

```js
supabase.from('experience').select('*')
  .order('created_at', { ascending: false })
  .lt('created_at', cursor)     // 첫 페이지는 이 줄 빼기. 다음 cursor = 마지막 행의 created_at
  .limit(20)
```

내 것만 나옵니다 (DB가 남의 행을 숨김). `.eq('user_id', me)`는 붙여도 되고 안 붙여도 됩니다.

## 삭제

```js
supabase.from('experience').delete().eq('id', id)
```

회차 기록은 같이 지워집니다. 사진 파일 정리는 사진 저장소 작업 때 정합니다.

## 회차 기록 (진행 중 활동만)

```js
const { error } = await supabase.from('experience_log').insert({
  id: uuid(),                 // 앱이 만듦. 다시 보낼 때도 같은 id
  experience_id: expId,       // 내 경험 + status 'in_progress' 여야 함
  log_date: '2026-11-16',     // 안 보내면 오늘
  situation_chips: ['바쁨'],   // 1~2개
  emotion_chips: ['뿌듯'],     // 딱 1개
  one_liner: '...',           // 100자
  extras: {},                 // 접힌 선택 항목
})
if (error?.code === '23505') { /* 같은 id 가 이미 있음 = 전에 저장 성공한 것. 성공으로 처리 */ }
```

- 끝난 활동이나 남의 경험에 달면 권한 에러(`42501`)가 납니다
- 수정할 수 있는 칸: `log_date`, `situation_chips`, `emotion_chips`, `one_liner`, `extras`

## 에러 코드 (Supabase가 주는 `error.code`)

| code | 뜻 | 앱에서 |
|---|---|---|
| `23514` | 제한 위반 (글자 수, 칩 개수, 목록 밖 분야 등) | 앱에서 먼저 막아야 하는 것. 나오면 버그 |
| `42501` | 권한 없음 (못 쓰는 칸, 남의 것, 끝난 활동에 회차 기록) | 버그거나 화면 상태가 오래된 것 |
| `23505` | 같은 id 이미 있음 | 회차 기록이면 성공으로 처리 |

글자 수·개수 제한은 DB가 마지막에 막는 것이고, **화면에서 먼저 막아 주는 게** 좋습니다.

## 서버로 가는 것 (앱이 직접 안 함)

- 공식 활동 검색·등록: `/activities/search`, `/activities` (곧 만듦)
- 정리 확인·흐름 요약: `/summarize`, `/flow-summary`
- 공개: `/publish/*`
- 질문 생성은 앱이 부르지 않습니다. 저장하면 DB가 재현 서버에 알려서 자동으로 만들어집니다
