# 임의로 정한 것들 — 검토 요청

이 문서는 2026-10-26~27 파이프라인과 1차 지도를 만들면서 **회의에서 정해지지 않아 구현자가 임의로 정한 모든 것**을 적은 목록입니다. 각 항목에 왜 그렇게 했는지, 다른 선택지는 무엇인지, 어디를 고치면 바뀌는지를 적었습니다. 팀이 보고 "이건 아니다" 싶은 항목부터 바꾸면 됩니다.

표기: ★★★ 결과에 영향이 크고 팀이 꼭 봐야 함 · ★★ 보는 게 좋음 · ★ 기술적 기본값, 급하지 않음

활동 유형 9개에 맞춰 직접 지은 검색어입니다. 처음 썼던 "썰·경험담" 류는 공포·연애 영상만 나와서 버렸습니다.

- 결과 편향: 대외활동·서포터즈(105장)와 아르바이트(78장)가 많고 학과 전시·학생회(각 17장)가 적음. 검색어 수가 유형별로 2~4개로 고르지 않은 탓.
- 바꾸는 곳: `QUERIES`. 추가하면 기존 영상은 건너뛰고 새 것만 붙음.

**1-2. 검색 조건** ★
`type=video, regionCode=KR, relevanceLanguage=ko, videoDuration=medium(4~20분), safeSearch=moderate`, 검색어당 2페이지(최대 100개). 쇼츠(4분 미만)와 20분 넘는 영상은 처음부터 제외됨. 하루 할당량(10,000유닛) 안에서 돌리려고 2페이지로 제한.

**1-3. 제목 제외 정규식** ★★
`소름|무서|살인|공포|괴담|귀신|심령 | 남친|여친|썸|전남|전여|손절|바람|소개팅|연애 | 쪽팔|수치|현타|메이크업|화장하면서|빌런 | 남의 썰|남의썰|구독자 사연|사연 모음|사연읽 | 협찬|광고(아님 제외)|[AD]|알바천국|알바몬`
- 제목만 보고 거르므로 오탐이 있음(예: "바람" 들어간 정상 제목). 걸러진 영상은 저장되지 않아 복구 불가. 2,346개 수집됐으니 양은 충분.

**1-4. 저장 항목** ★
video_id, 제목, 길이, 상태만. 채널명·작성자 정보는 처음부터 저장하지 않음(개인정보 최소화).

## 3. 카드 추출 (`extract_experience.py`, `extract_experience_gemini.py`)

**3-1. 모델** ★★
- 자막 → Claude `claude-haiku-5-5`(effort medium). Sonnet과 34개 비교에서 범위 판정 31/34 일치, 카드 문장 품질 동등, 비용 1/15라 선택. 사용자 동의함.
- 영상 → Gemini `gemini-3.5-flash-lite`, `media_resolution=LOW`, `temperature=0.2`. 10분 이하 영상만 대상(비용 절감). 실측 영상당 약 16원, 범위 안 판정 80%.
- 두 모델이 만든 카드가 한 파일에 섞여 있음. 출처는 `usage_log.csv`의 model 열로 구분 가능.

**3-2. 제외 기준에 추가한 4가지** ★★★
7차 회의 기준(소비만 한 경험·연애·공포·남의 사연 제외)에 더해 프롬프트에 넣은 것:
1. 정보 전달·강의·광고·제품 소개 위주로 화자의 행동 서술이 없는 영상
2. 기업·방송이 제작한 콩트·예능 형식의 연출된 알바/인턴 콘텐츠
3. 활동 소개나 모집 안내만 있고 화자가 실제로 한 일이 없는 경우
4. (자막 방식) 자막이 깨져 한 일을 확인할 수 없는 경우 → 모델이 스스로 제외
- 2번은 애매함: 기업이 만든 "실제 인턴 인터뷰"는 포함됐음(예: 신용보증기금 인턴 인터뷰). 연출 vs 실제의 경계는 모델 판단에 맡겨져 있음.

**3-3. 활동 유형 9개** ★★
7차 회의 7개(동아리·학회 / 팀플·공모전 / 아르바이트 / 대외활동·서포터즈 / 학생회·행사 운영 / 봉사·멘토링 / 학과 전시)에 **개인 프로젝트, 인턴**을 추가. 매핑 규칙도 프롬프트에 넣음: 현장실습·인턴십 → 인턴, 수업 팀프로젝트·해커톤·공모전 → 팀플·공모전. 회의에서 "인턴 등"이라고 했지 유형 목록에 없었음.

**3-4. 추출하는 필드와 안 하는 필드** ★★★
- 추출: 활동명, 활동 유형, 역할, ① 상황, ② 내가 한 일, ③ 어땠나
- 추출 안 함: **장소, 기간, 상태** — 유튜브 영상에서 신뢰할 수 없고 테스트용이라 뺌. 실제 앱에서는 사용자 입력 필드.
- **한 줄 요약**은 추출 단계가 아니라 태그 단계(4-2)에서 생성.
- 문장 길이 지침: ① 1~2문장, ② 2~3문장, ③ 감정 단어 1~2개 + 설명 1~2문장, 전부 1인칭 한국어. 이 길이도 임의.
- 활동명은 "가능하면 공식 명칭"으로 지시 → 유튜브 카드에는 실명 기관·행사명이 들어 있음(예: 쿠팡 시흥2센터). 공개 범위 설정과 관련해 팀 확인 필요.

**3-5. 영상 하나 = 카드 한 장** ★★ 여러 활동이 나오면 "가장 구체적으로 한 일을 말한 활동 하나"만. 7차 회의의 "하나의 활동 = 하나의 카드"를 따르되, 긴 영상의 다른 활동은 버려짐.

**3-6. 저장 조건** ★ `in_scope=true` 이고 ②가 비어 있지 않을 때만 저장(7차 1차 검수 규칙). 둘 중 하나라도 아니면 status=none.

**3-7. embedding_text 열** ★★ 활동명+유형+역할+②+③를 공백으로 이은 것(7차 정의). ①은 넣지 않았고 "정리 정보"는 없음. **다만 지도 생성에는 이 열을 쓰지 않고 ③만 씀(5-2).** 열 이름이 오해를 부를 수 있음.

**3-8. 기타** ★ 모델 출력 끝의 따옴표·괄호 찌꺼기 제거(`_clean`), 제목 HTML 엔티티 해제, 429/402/5xx는 중단하고 pending 유지.

**4-1. 태그 종류와 시드 어휘 45개** ★★★
회의에는 "같은 태그(예: 커뮤니케이션)면 연결"만 있었고 태그 체계는 없었음. 세 종류로 나누고 예시 어휘를 프롬프트에 넣음:
- 역량(12): 커뮤니케이션, 기획, 리더십, 문제 해결, 협업, 꼼꼼함, 책임감, 체력, 끈기, 창의성, 적응력, 시간 관리
- 일의 성격(18): 고객 응대, 콘텐츠 제작, 영상 편집, 글쓰기, 교육·지도, 행사 운영, 판매·영업, 조리, 재고 관리, 홍보·마케팅, 디자인, 데이터 분석, 개발, 인터뷰·취재, 사진 촬영, 발표, 자료 조사, 번역·외국어
- 분야(15): 교육, 식음료, 문화·예술, IT, 환경, 지역사회, 아동·청소년, 패션, 스포츠, 미디어, 금융, 해외
- 금지: 활동 유형 자체(아르바이트·인턴…), 고유명사, 감정 단어
- 결과: 모델이 거의 시드 안에서 골랐고(83개 중 시드 밖은 대부분 1장짜리), 가장 많이 나온 태그는 협업(181), 기획(123), 콘텐츠 제작(97). **협업·기획이 너무 흔해서 연결 변별력이 낮음** → 가중치나 제외 검토 필요.

**4-2. 한 줄 요약** ★ 40자 이내, 1인칭 생략한 명사형. 7차 템플릿의 "한 줄 요약" 자리를 여기서 채움.

**4-3. 카드당 3~6개** ★ 평균 4.5개 나옴. 적으면 연결이 희박, 많으면 전부 이어짐.

**4-4. 어휘 정리: 3장 이상 등장한 태그만 연결에 사용** ★★ (사용자 동의) 83개 중 42개 남김. 버린 41개는 `map/tags_raw.json`에 남아 있고 `map/tag_vocab.json`을 손보면 바뀜. 동의어 병합(예: "교육"과 "교육·지도"가 둘 다 살아 있음)은 하지 않음.

**4-5. 모델** ★ Haiku 5.5, effort medium, 4개 동시 호출. 카드당 약 2원.

## 5. 밑지도 (`build_map.py`)

**5-1. 임베딩 모델** ★ Gemini `gemini-embedding-001`, 768차원, `task_type=CLUSTERING`, L2 정규화. 이유: 키가 있고 사실상 무료. Claude는 임베딩 API가 없음. 모델을 바꾸면 밑지도와 배치 벡터를 전부 다시 만들어야 하고, 앱이 같은 모델을 호출해야 함.

**5-2. 임베딩 입력 = ③ 어땠나만** ★★★ (사용자 선택, 선택지는 구현자가 만듦)
세 가지를 비교해 가장 활동 종류를 가로지르는 것을 골랐음.
| 입력 | 섬에서 가장 많은 유형의 비율 |
|---|---|
| 활동명+유형+역할+②+③ (7차 정의) | 83% |
| ②+③ | 61% |
| ③만 (채택) | 45% |
- 대가: 섬 경계가 느슨함(2D 실루엣 0.58→0.39). ③가 짧은 카드(1~2문장)는 위치가 불안정할 수 있음.
- 앱에서 사용자가 ③를 성의 없게 쓰면 배치가 엉뚱해짐 → 입력 UX에서 ③를 유도해야 함.
- 바꾸는 곳: `--embed-fields all|review|feeling`. `regions.json`의 `meta.embed_fields`에 기록되고 `place_card.py`가 그걸 읽어 같은 규칙을 씀.

**5-3. 2차원 좌표: t-SNE** ★★
`metric=cosine, perplexity=30, init=pca, random_state=0`, 결과를 50~950 범위로 늘림.
- t-SNE는 새 점을 직접 넣을 수 없어서 새 카드는 이웃 평균으로 배치(6-3). UMAP은 새 점 변환이 되지만 설치돼 있지 않아 안 씀.
- 좌표는 데이터가 바뀌면 전체 모양이 바뀜. 6차 회의에서 "모양은 바뀌어도 되고 이름은 유지"로 합의된 부분.
- perplexity 30은 기본값. 점이 469개라 10~50 어느 값이든 큰 차이 없을 것으로 봤으나 실험하지 않음.

**5-4. 섬 나누기: 2D 좌표에서 KMeans, k는 8~12 중 실루엣 최대** ★★
- 처음엔 768차원에서 묶었는데 지도 위에서 섬이 길게 겹쳐 보여서 2D에서 묶는 것으로 바꿈. 의미는 t-SNE가 이미 비슷한 것끼리 모아 놓으므로 유지됨.
- 8~12 범위는 "폰 화면에 몇 개가 들어가나"(6차 재현 질문, 명금 답변 예정)를 모르는 상태에서 임의로 잡은 범위. 현재 8개 선택됨.
- KMeans는 섬 크기가 비슷해지는 경향이 있어 작은 소수 주제는 큰 섬에 흡수됨.
- 바꾸는 곳: `--k N` 또는 `--k-range 6 14`.

**5-5. 섬 이름** ★★★
- 모델: `claude-sonnet-5-5`, effort high, 섬 전체를 한 번에 넘겨 이름이 겹치지 않게 함.
- 입력: 섬마다 ③ 후기 15개(임베딩 중심에 가까운 순), ② 6개, 감정 단어 빈도 8개, 활동 유형 분포(참고용·이름에 금지).
- 형식 강제: 「〇〇과 〇〇의 지형」, 앞 두 낱말은 추상 명사(예시로 사랑·인간·인내·성취·용기·환대·몰입·연대·서툶·발견·책임·자유 제시), 지형은 숲·들판·언덕·바다·강·항구·골짜기·광장·섬·고원. 활동 명칭·장소·직무 단어 금지. 설명형 이름(name_plain)과 한두 문장 설명(description)도 같이 생성.
- 감정 단어 추출은 ③ 첫 문장을 "과/와/·/,"로 자른 조잡한 휴리스틱.
- 캐시: 섬 멤버 구성이 같으면 다시 짓지 않음(`map/region_names.json`). 이름을 바꾸고 싶으면 이 파일을 직접 고치면 됨.
- 첫 버전은 활동 카테고리를 감성적으로 포장한 이름이 나와서(예: "이야기를 담는 취재 숲") 사용자 지적으로 후기 기반으로 바꿈.

**5-6. 섬 통계** ★ 반경 = 멤버 거리 80퍼센타일 / 대표 태그 = 섬 내 비율 ÷ 전체 비율(lift) 상위 5, 섬 내 3장 이상 / 섬 번호는 크기순.

**5-7. 가상 사용자** ★ (사용자 동의) 3명×4장을 활동 유형이 섞이도록 돌아가며 뽑고 밑지도에서 제외. seed 0. 실제 팀 목 데이터가 오면 교체.

## 6. 연결과 배치

**6-1. 연결 규칙** ★★★
- 두 카드의 공유 태그 수 w ≥ 1이면 연결(7차 규칙). 정렬은 w 내림차순 → 코사인 유사도 내림차순.
- **내 카드끼리(사용자 핑 사이)는 카드당 상위 3개만** 선으로 그림(6차 "작은 화면에 선 두세 개").
- 밑지도 카드의 "이어진 활동"은 상위 10개.
- 뷰어용 전체 간선은 w ≥ 2 또는 노드별 상위 6개만 저장(15,629개). 화면의 "모든 연결" 토글은 w ≥ 3만 그림(성능).
- 태그 공유만 보므로 협업·기획처럼 흔한 태그 하나로도 이어짐. 태그별 가중치(희귀할수록 높게)는 넣지 않음.

**6-2. 선택 카드의 회색 선** ★ 뷰어에서 점을 누르면 밑지도 전체에서 태그 공유 상위 10개로 선을 그림. 작동 확인용이고 실제 앱의 "내 지도"에는 내 카드끼리 선만 두는 게 맞음.

**6-3. 새 카드 배치 규칙 `place()`** ★★★
- 새 카드 임베딩과 밑지도 벡터의 코사인 유사도 상위 10개 이웃 → 좌표는 유사도⁴ 가중 평균 + ±6 지터 → 섬은 이웃들의 유사도 합이 가장 큰 섬.
- 유사도⁴는 가까운 이웃에 더 끌리게 하려는 임의의 지수. 지터는 같은 자리에 겹치지 않게 하려는 값.
- 대안 `--placement centroid`: 가장 가까운 섬 중심 근처(반경 60% 안) 랜덤. 밑지도 벡터를 보관하지 않을 때 씀. 정확도는 떨어짐.
- 테스트: 손으로 쓴 카드 3장이 기대한 섬에 떨어졌고 최근접 유사도 0.94~0.96. 3장뿐이라 충분한 검증은 아님.

## 7. 뷰어 (`map_template.html`)

**7-1. 시각 표현** ★
- 섬: 멤버 점의 바깥 8%를 뺀 convex hull을 22단위 넓혀 곡선으로. 색은 중립 회색 한 가지(섬 8개를 색으로 구분하면 접근성 검증을 통과하지 못함).
- 사용자 3명: 파랑·주황·청록(색각 이상·대비 검증 통과한 팔레트). 4명 이상이면 색만으로 구분 불가 → 모양 등 추가 필요.
- 밑지도 카드: 회색 점. 핀 라벨은 활동명 14자까지.
- 다크 모드, 목록 표, 섬 표, 태그·유형·섬·사용자 필터. 이건 확인용이고 앱 화면 설계(명금·하영)와 무관.

**7-2. 지도 위 표시 안 한 것** ★ 섬 경계 밖 공간의 의미 없음, 섬끼리의 거리 의미 없음(t-SNE 특성). 앱에서 "거리"를 의미로 쓰려면 다른 축소 방법 필요.
